# Software Design and Engineering Narrative

The artifact I chose for my Software Engineering and Design enhancement is the weight tracking application I created on August 22nd, 2025. This application was created as my final project in the CS-360: Mobile Architecture and Programming course. I designed this application with the intent of creating a simple, efficient mobile application that enables users to quickly enter their daily weight, the date of entry, daily intake, and daily exercise. The primary features of my application are a grid that displays daily entries, the ability to edit/delete entries as desired, and an SMS notification feature if the user wants to receive updates on their weight goals. Over time, the grid of the user’s daily entries would provide information about their daily habits and how their weight has changed.

I included this artifact in my ePortfolio because it showcases my ability to seamlessly integrate different functions and customization options into a cohesive, professional application. The specific components of the artifact that showcase my skills and abilities are the login/create account functions, the navigational capabilities, the grid display with data entry, the optional SMS feature, and customization through account settings. The login/create account functions show my understanding of creating a database, storing information in a database, and utilizing unique information to authenticate credentials. The navigational capabilities show my ability to seamlessly transition between different screens while passing crucial information between each screen. The grid display with data entry shows my skills in creating a visualization of personal/unique data that’s specific to the username, and it shows my skills in creating a fluid grid that can have entries altered or deleted as desired. The optional SMS feature shows my ability to create a feature that can enhance the experience of an application but isn’t required to make the application operational. This also shows my ability to link my application to the device settings while adhering to the principle of least privilege. The application customization through the account settings shows my competency with updating databases, establishing an application theme for the device, and creating a multi-level authorization system for enabling SMS notifications.

The enhancements I performed on my artifact, compared to my initial application, are adjusting the logic of my code to increase performance and provide more error checking, adding a navigation screen as the “hub” of my application, adding an account settings screen that allows for users to change their username, password, theme, and notification preferences, and appropriately anchoring and constraining my on-screen elements to be functional across different mobile devices and orientations.

As I was enhancing and modifying my artifact, I learned it’s crucial to take time to read through the current code and understand it prior to attempting any enhancements. My mindset going into the enhancements was to immediately start attempting the implementation of the new features like the account settings screen. After adding the methods to make the screen functional, I realized I had some major flaws with the implementation of my features that sacrificed the usability of my other screen. For example, I implemented the theme selection in the account settings screen, but when switching to different themes, the text colors weren’t correctly switching with the theme. This led to black text on a black background and white text on a white background, which made the screen impossible to navigate. This happened due to my current implementation of my app theme, which didn’t allow for certain colors to be present when navigating a specific color library. Another example was when I implemented the notification preference in the account settings, I accidentally created a deadlock with how the setting interacted with my SMS notification screen. Both examples led to many hours of trial-and-error that could’ve been avoided if I took the time to read and understand my code. A challenge I faced, that also served as a lesson when developing the on-screen elements of applications, is the anchoring and constraints of each on-screen element. The lesson I learned from this challenge is to take a proactive approach to setting the anchor points and constraints of on-screen elements as they’re created, not a retroactive approach once everything is on the screen. As I was attempting to adjust my anchor points and constraints, I encountered multiple issues with layout fidelity warnings, improper preview rendering, and discrepancies between different device sizes and orientations. Although I didn’t completely find solutions to the scaling and orientation issues across all devices, I did create an operational version of the application across multiple devices, sizes, and orientations.
