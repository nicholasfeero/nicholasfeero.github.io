# Algorithms and Data Structures Narrative

The artifact I chose for my Algorithms and Data Structures enhancement is the Task JUnit Testing program I created on February 2nd, 2025. This program was created as an assignment for my CS-320: Software Testing, Automation, and Quality Assurance course. I designed this program to quickly run JUnit tests that add, remove, and update tasks that exist on a task list, and maintain restrictions like character limit and null data fields for each data entry. By altering the testing criteria and data entry variables, the output will determine whether the implemented tests operate effectively by showing whether the test appropriately passes or fails.

I included this artifact in my ePortfolio because it showcases my ability to effectively create, alter, and read unit tests for different variables and restrictions while maintaining a functional list of data entries. A specific component of my artifact that showcases my skills is the implementation of efficient algorithms that examine data entries, compare them against the testing criteria, and display accurate results to the unit tests. Another component of my artifact that shows my abilities in coding is the translation of these tests from Java to C++. This displays a core understanding of operating in different IDEs, the shared and unique aspects of different coding languages, and the basic functionality of unit testing.

When enhancing and modifying my artifact, a major lesson I learned, that also acted as a challenge, was the differences in how Java and C++ handle similar operations. I had to change the way my C++ code handled memory with list maintenance, called exceptions, how it performed character length checks, and how it threw arguments. These functions are possible in both Java and C++, but a direct translation between the two languages wasn’t possible due to Java behaviors not directly mapping to C++ behaviors. Another challenge that I faced when working through my enhancement was figuring out case-insensitive ID checks. Since it had been some time since I’d engaged with coding from scratch in C++, I’d known that Java has built-in functionality for case-insensitivity checks but had forgotten that C++ doesn’t. Thus, to successfully perform my unit tests, I had to manually create a helper method that performed case-insensitivity checks with task IDs. Initially, this created a lot of confusion when testing my code which led to multiple errors and a lot of trial-and-error, but as I performed research utilizing my trusted resources, I was reminded of C++’s limitation with built-in case-insensitivity checks and was able to create a functional helper method and correctly perform my unit tests in C++.
