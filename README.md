# Databases Narrative

The artifact I chose for my Databases enhancement is the Animal Shelter CRUD Operations application I created on April 27th, 2025. This application was created as a project for my CS-340: Advanced Programming Concepts course. I designed this application to be a tool that has comprehensive coverage regarding the animals in an animal shelter database. With access to this application, end-users can filter the database to search for animals that satisfy certain criteria (e.g. Water Rescue, Mountain or Wilderness Rescue, etc.) and can observe each filter option with multiple outputs. For example, with each display of the database, there will be an associated chart with text entries per animal, a pie chart that displays the breed distribution of the current database display, and a geographical chart that presents the location of each animal on the current database display. In this application administrators have access to CRUD (Create, Read, Update, and Delete) operations through the utilization of MongoDB. By accessing the MongoDB service, any user that’s granted administrative privileges (readWrite) can perform these operations to maintain the database.

I selected this artifact for my ePortfolio because it showcases my ability to effectively implement secure methods to protect sensitive data without compromising the functionality of an application. A specific component of my artifact that highlights my skills in security is the implementation of TLS encryption to protect data as it’s in transit from MongoDB to Dash. To implement this method, I created local certificates such as a server certificate with a private key, a client certificate with a private key, and a Certificate Authority (CA) certificate. After I created these certificates, I checked the MD5 hashes of each certificate and key to confirm the appropriate hashes matched, then created a test file to confirm the TLS encryption applied to my application. A specific component of my artifact that highlights my skills in authentication is introducing a user authentication method that requires correct credential input before allowing access to the program. Prior to this implementation, the application would simply launch by taking the credentials (username and password of established user) as parameters. Thus, it would load straight into the application. Now, I formatted my application into containers (login and database) and wrapped the display within the login container. This creates another level of authentication, where the individual accessing the application must know the credentials for logging in, or must be granted their unique login credentials as an authorized user for the database in MongoDB. If the user fails to provide correct login credentials, they’ll remain stuck in the login container and will not be granted access to the application.

When enhancing and modifying my artifact, I encountered many challenges. The first challenge I encountered was the implementation of encryption at rest. Since I’m utilizing Windows 11 Home Edition, and since I’m using the community version of MongoDB, the local and database methods for encrypting data at rest aren’t available to me. For a company, it would be a mandatory paid expense to acquire the tools for encrypting data at rest. However, given my circumstance, it wasn’t a feasible implementation. Another challenge I encountered was implementing the user authentication system. Although I have methods for verifying a user’s credentials to gain access to the application, I couldn’t access the MongoDB server due to local machine limitations. When I originally created this project, it was on a virtual desktop. After hours of installations, transferring files to appropriate locations, and establishing the database on my local system, I may have accidentally lost the ability to start my current installation of the MongoDB Server through my system. To solve this issue, I reinstalled the MongoDB Server on my local device and ensured the mongod executive file had a reachable path with appropriate permissions. From here, I was able to access the database through the MongoDB Server connection, and I was able to utilize environmental variables to remove hardcoded usernames and passwords.

A lesson I’ve learned through these enhancements is to frequently test code even after the smallest of changes. Through not testing my code enough, I buried errors with the functionality of my application and local software that took hours to solve. I performed a lot of research and preparation prior to implementing the methods, however, tackling the problems in real-time is a lot different than conceptualizing the problems. In future work, I will test more frequently and create a log of when bugs occur, what caused them, and how they were solved.
